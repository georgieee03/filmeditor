# Premiere Pro workflow and feature comparison

Reviewed on 2026-10-08 against Adobe's current Premiere desktop documentation and the FilmEditor source/runtime available at that date. This is a feature map for planning the rebuild; it is not a feature-count score or a claim of Premiere compatibility.

## What “90%” can and cannot mean here

Adobe's desktop documentation describes a large, changing product that spans editing, media management, effects, color, sound, graphics, export, collaboration, and integrations. Adobe's feature page also includes beta and account-dependent services. Without a defined feature list, weighting, Premiere version, operating system, and plan, a percentage such as “90%” has no reproducible denominator. FilmEditor cannot currently support that percentage claim.

The user's request for a Premiere-like interface and feature coverage is a product direction. The current application has a custom native Mac shell around FilmEditor's own four-panel editing interface. It resembles a conventional non-linear editor at a broad level, but it is not an exact copy of Premiere's UI. The table below states which FilmEditor actions have a dedicated control, which depend on the generic engine-tools/Codex route, and which are absent or materially narrower.

Status labels mean:

- **UI** — a dedicated FilmEditor control exists and the named core action has acceptance evidence.
- **Engine-tools-only** — the installed MLT/Shotcut MCP schema or a FilmEditor MCP tool can perform some of the operation, but FilmEditor has no dedicated editing control for it.
- **Partial** — FilmEditor exposes a narrower action or workflow than the Adobe feature being compared, or evidence covers only a limited format/path.
- **Missing** — no supported FilmEditor UI or exposed editor-tool workflow was found for the feature. This does not assert that MLT is incapable of the underlying media operation.

The current evidence tier and its limits are recorded in [VALIDATION.md](VALIDATION.md). The frozen source suite passed 161 tests. The installed bundle passed scoped launch/reopen, playback, persistence, quickstart, media-info/AI dialogs, music Fit, no-TCP and shared-MCP checks. The corrected live native AI button authored a synthetic 30-frame clip, accepted MLT preview and render-status results without failed MCP calls or shell recovery, fully decoded the export, recorded no approval events, left the source unchanged, and retained a valid app signature after the turn. The source-backend live Codex test passed the same bounded edit/export flow. Browser acceptance used generated synthetic media and validates advanced browser-to-MLT operations and final decode; the native app opened the advanced dialog but did not execute those edits in WKWebView. Final general launch/reopen and source-to-bundle equality passed. Native preset interaction, Finder-originated file drop, full native catalog/credit workflow, real camera Log/HDR handling, long-form reliability, sustained 4K playback, and color accuracy remain unverified.

## Highest-impact bounded next steps

1. **Expand workspace customization.** The current Editing, Color, Audio, and Graphics choices only adjust dimensions in the same fixed panel layout. Saved panel visibility, movable panel placement, docking, and floating panels would close a larger part of the gap without claiming an exact clone.
2. **Expand timeline-native trim interactions.** The current dialog exposes numeric roll, slip, and slide edits. Add direct pointer/keyboard trim modes, ripple editing, and a Trim monitor that previews both sides of an edit; acceptance should cover downstream tracks and marker behavior.
3. **Build a real effect and keyframe inspector.** Browse installed MLT services, show each service's actual parameter schema, and edit clip keyframes on a visible lane/curve. Keep the current simple controls as a clear subset and report unavailable services accurately.
4. **Complete native music acceptance and expand caption delivery.** Exercise Openverse search/import and revision-scoped export credits in WKWebView. Keep the tested local-song Fit and browser export evidence scoped. The caption UI imports and edits SRT; add sidecar export and supported styling before attempting transcription or text-based editing.
5. **Treat real-time GPU playback, multicam, color scopes/management, collaboration, Adobe plug-ins, and `.prproj` support as separate architecture or interoperability projects.** These are major product gaps; a visual UI pass alone cannot close them.
