# Independent implementation review

Review date: 2026-10-08. Scope: the reconstructed editor, manual timeline operations, Codex app-server integration, media/render lifecycle, native macOS host, music, and automatic media setup. This is an implementation review, not a certification of Premiere feature parity or camera-specific color fidelity.

## Evidence and current status

The review inspected the actual source, the installed Shotcut MCP implementation, the generated Codex protocol schema, and the local synthetic acceptance reports. Real MLT/Chrome acceptance and the later AppKit/WKWebView acceptance are separate evidence. Automated native playback does not establish Finder or file-dialog interaction. A separate real-engine spot check confirmed that the new manual lock check rejects deletion from a locked video track. It used a temporary synthetic source and removed the temporary workspace afterward.

The live Codex report shows a shell command completing under `approvalPolicy: never` and `sandboxPolicy.type: dangerFullAccess` with no approval events. This proves that bounded interaction, not every possible external connector action. The installed protocol schema supports the separate `auto_review` reviewer selection. Full access and automatic approval review are different permission modes.

## Corrective findings

| Priority | Finding | Correction or acceptance requirement |
| --- | --- | --- |
| P1 | Track lock was only checked by some pointer handlers. The installed MLT editor treats `shotcut:lock` as metadata and still accepts ordinary edits. Keyboard deletion, razor, inspector edits, and destination moves could change locked tracks. | Enforce manual-operation source, destination, and filter-owner locks in `Editor.edit`. The direct locked-track deletion check now passes; cover other entry points and keep explicit unlock possible. |
| P1 | Editing and history requests carried a revision but no project identity; the backend resolved whichever sequence was active at handling time. Revision hashes identify bytes, not a unique file. | Bind edit/history/render requests to the displayed project path, retain that captured path for the result, and reject a changed selection. A copied MLT can have the same hash; separately created empty sequences in the spot check had different hashes. |
| P1 | Proxy preparation held the same lock as edit/undo for the whole FFmpeg transcode. Timeline edits also waited behind durable renders despite their immutable input snapshot. | Use a separate media lock and allow metadata edits while a durable export uses its saved snapshot. Still serialize heavy media work. A synchronous MCP preview occupies the single engine RPC worker and remains a responsiveness limit. |
| P1 | Native import/upload and API lifecycle checks must participate in project deletion/close coordination. Media preparation subprocesses also need app-owned cancellation. | Check archival and increment active work under the same lifecycle lock. Count in-flight native imports and unfinished uploads. Verify quit during proxy work leaves no owned FFmpeg process and does not terminate unrelated processes. |
| P1 | The heavy-work wait inspected durable job summaries without calling `render_status`. The installed engine only reconciles a dead supervisor in `render_status`, so a stale running job could block later work indefinitely. | Reconcile active job IDs before waiting. An orphaned but live renderer still occupies resources and needs explicit recovery rather than silent extra rendering. |
| P2 | Frame preview opened the mutable sequence file and labeled the result with an earlier UI revision. An older in-flight frame could also replace a newer playhead during debounce. | Render a verified immutable sequence snapshot and return its revision. Only show the response when project, revision, frame, and request identity still match. |
| P2 | Codex `edit_project` calls bypassed the manual history recorder, disabling UI undo when AI changed the timeline. | Share committed-edit history across the manual and MCP entry points, or state the narrower undo capability explicitly. Engine backups remain separate recovery evidence. |
| P2 | Sharing the history recorder alone left concurrent MCP commits able to record out of order. The engine response and observer were separate critical sections. | Hold the same reentrant editor lock across the engine commit and history observer. A concurrency regression now pauses the first observer and verifies that a second engine commit cannot overtake it. |
| P1 | A failure persisting undo history occurred after the MLT edit committed, but propagated as an ordinary edit failure. The new soundtrack caller then deleted audio already referenced by the saved sequence. | Preserve the committed result, expose a history warning, and disable unreliable undo until persistence recovers. A regression through the actual shared forwarding path now verifies that committed music survives this failure. |
| P2 | A vertical-only clip drag did not cross the horizontal movement threshold, so changing track without changing time was ignored. | Measure pointer movement in both axes; test V1 to V2 with an unchanged X coordinate. |
| P2 | Selected source and program previews cached media URLs beyond their one-hour signatures. Returning fresh render-job URLs alone did not update the selected program. | Renew active source, thumbnail, and program URLs and preserve playback position; test expiry without waiting an actual hour. Native capabilities need the same lifecycle treatment. |
| P2 | Effect controls did not read the selected clip's saved values. Applying volume could reuse another clip's scale/opacity. | Hydrate owned filter values when selecting a clip. Clearly label constant-value application; do not silently represent a keyframed effect as a complete editable animation. |
| P2 | Render history took the newest 30 jobs globally before filtering by workspace. Another project's jobs could hide this project's recoverable preview. | Follow the engine's `next_cursor` until the per-workspace quota is satisfied, and retain explicit active job identities. Bind recovered previews to both project and revision. |
| P2 | Agent-requested frame extraction bypassed the shared heavy-work semaphore. | Put uncached FFmpeg extraction under the same heavy-work limit and constrain decoder/output threads. Cached reads should remain cheap. |
| P2 | Codex lifecycle notifications were handled without checking the originating thread/turn. | Only the active parent turn may change its busy/stop state. Child activity must not clear that state or replace the parent's turn ID. |
| P1 | The installed Codex MCP parser rejected successful preview images and completed-render resource links when upstream content annotations contained floating-point `priority: 1.0`. The model could recover through other tools, masking the protocol failure in an output-only acceptance check. | Normalize optional content annotations only at FilmEditor's public stdio MCP boundary. Preserve structured results, pixels, artifact links, error status, and the original response for local consumers. Verify the actual parser as well as final exported media. |

## Music review and remaining evidence limits

The [music research and review](MUSIC_RESEARCH.md) records the primary sources, supported catalogs, licensing boundaries, soundtrack behavior, and network constraints. Sixteen independent regressions in `tests/test_music_review.py` pass. They cover network and metadata rejection, shared connection deadlines, actual standard-library HTTP response ownership, stale sequence handling, committed-media retention, and credits on the raw Codex export path. Source inspection confirms credit generation uses the immutable render XML and preserves a running job when a sidecar write fails.

Real synthetic MLT evidence verifies an eight-second fitted soundtrack, a source offset, exact sample/frame duration, overall fades, one shared undo transaction, unchanged picture/dialogue, full export decode, and both the music and dialogue frequencies in the exported mix. This is stronger than merely finding an audio stream, but remains a synthetic test. The installed native smoke also exercises fitting and reopening a local song.

The reviewer read the separate successful live Openverse record: one anonymous Jamendo song import, full 228.74907-second audio decode, preserved CC BY 3.0 metadata and original, and no third-party song in the repository. Browser Music-dialog acceptance also passed real local import, fitting, export with credits, reload, and inert mocked catalog markup. These are separate evidence paths; one successful catalog song does not establish every provider or every result.

No unresolved release-blocking correctness defect remains in this reviewed scope after these corrections. The final release must still use the rebuilt source and report the aggregate tests rerun after the last changes. The remaining limits are explicit:

- Finder-originated external drag/drop is not established by the internal pointer-drag test or native open-panel test.
- Rapid source replacement, full keyboard accessibility, and every cancellation/navigation race have not received exhaustive native interaction testing. Capability forgery/expiry and confinement have unit coverage; origin and task-cancellation defenses also received source review.
- Actual owned-child cancellation has regression evidence; quit during every media preparation stage is not exhaustively exercised. Durable render recovery and ordinary app/backend shutdown are separately tested.
- Beat timing is an estimate; fitting does not recut picture, automatically duck dialogue, guarantee seamless loop joins, or certify the final mix. Public catalog metadata is not independent rights clearance, and the catalog does not contain every commercial song.

## Primary references and design conclusions

- [OpenAI subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): independent review is suitable delegated work; the user explicitly requested the agent split. The parent collects the findings, while file ownership avoids conflicting writes.
- [OpenAI AGENTS.md guidance](https://learn.chatgpt.com/docs/agent-configuration/agents-md): repository instructions are loaded through the project hierarchy. Keep setup, validation, ownership, and evidence limits in the source handoff rather than relying on chat history.
- [OpenAI app-server](https://learn.chatgpt.com/docs/app-server): use the supported initialize/thread/turn lifecycle, explicit permissions, persisted thread identity, and event routing. Validate experimental fields against the installed binary's generated schema.
- [Apple WKURLSchemeHandler](https://developer.apple.com/documentation/webkit/wkurlschemehandler): a local custom scheme is supported for app resources. Stream media with bounded memory rather than loading an entire video into JavaScript.
- [Apple scheme-task cancellation](https://developer.apple.com/documentation/webkit/wkurlschemehandler/webview(_:stop:)): after cancellation, do not call the task's response/data/completion methods. Gate callbacks and cleanup on the native lifecycle.
- [Apple frame security origin](https://developer.apple.com/documentation/webkit/wkframeinfo/securityorigin): validate both the main frame and the expected scheme/host before exposing privileged native operations.
- [WebKit macOS WKWebView implementation](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/mac/WKWebViewMac.mm): the native view reports flipped coordinates, so a Finder drop must not invert Y a second time when translating into DOM coordinates.

The deliverable is a native macOS host with a WKWebView editor and separately installed local engines. Camera-specific Log/HDR/RAW, sustained long-form or 4K responsiveness, signed/notarized distribution, full keyboard accessibility, and complete Premiere parity require additional evidence or implementation. Preserve that distinction in the README and release claims.
