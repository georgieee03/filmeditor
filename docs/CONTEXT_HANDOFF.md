## User request and boundaries

- Deliver a native macOS video editor with direct timeline editing, local rendering, Codex editing the same project, an in-app quickstart, and a music workflow.
- New projects default to Codex full access: `approval_policy=never`, thread `sandbox_mode=danger-full-access`, and turn `sandboxPolicy.type=dangerFullAccess`. This is intentionally broad file and command access. Existing projects may retain a different saved permission mode.
- Native mode uses an AppKit/WKWebView shell loaded from `filmapp://app`, stdio JSON IPC to its Python backend, and an owner-only Unix-domain socket for external MCP. It must not start a TCP listener or launch an external browser.
- Preserve camera originals and unrelated projects. Keep generated media, user workspaces, private reports, runtime dependencies, app bundles, credentials, and machine-specific files out of the public repository.
- Keep evidence tiers explicit. Synthetic and short-form media checks do not establish real-camera compatibility, long-film reliability, color accuracy, or Premiere parity.

## Architecture and workflows

FilmEditor owns its editor UI and project model and uses the locally installed Shotcut MLT engine and FFmpeg for media operations. The Python source owns project state, revision-checked edits, IPC, Codex, and external MCP. The Swift AppKit app owns the window and child-backend lifecycle. The native, Shotcut-adapter, and Codex-MCP Python launches use `-B` to prevent bytecode caches from invalidating the ad-hoc-signed application bundle; this is not a permission boundary. The build bundles the selected relocatable Python runtime and pinned adapter source; Shotcut, Node, Chrome, and Codex remain installed dependencies. FilmEditor does not use Adobe’s proprietary engine or claim Premiere project compatibility.

The editor includes a media bin, Source/Program monitor tabs, inspector, Codex panel, and multitrack timeline. Direct controls cover import, clip placement, move, trim, split, duplicate, delete, snapping, track controls, undo/redo, basic brightness and saturation, preview, and export. Editing/Color/Audio/Graphics/Reset presets adjust dimensions in the fixed panel layout; divider changes persist locally. Browser acceptance verified preset and divider bounds at 1280×800. Native preset interaction was not specifically verified in the last installed bundle; verify it in the current rebuild.

The Edit tools dialog exposes numeric roll, slip, and slide, speed/reverse, an adjacent dissolve, title generation, sequence markers, and SRT import/edit. The browser-to-MLT synthetic acceptance passed, and the final native build opened the dialog; individual native edits remain unverified. Sequence previews are offline MLT renders, not Premiere-style real-time playback.

Automatic media setup uses local FFprobe facts and a deterministic reference group to configure a supported empty sequence once. Existing edits and explicitly chosen settings are preserved. Ambiguous timing, unsupported color evidence, HDR, and camera Log are surfaced for review; the detector does not claim a camera transform. A browser detection test passed on synthetic media with mocked Codex dispatch, and synthetic MLT acceptance passed rotated geometry/rational-FPS configuration plus a tagged-PQ render guard. The AI edit action sends a user brief through the existing Codex session; the live synthetic check configured a source, inspected frames, authored one 30-frame clip, rendered H.264, fully decoded the export, and recorded no approval events. It exercised the source desktop backend over app-server stdio and private Unix MCP, not the packaged native WKWebView. See [AI_PROVIDER_HANDOFF.md](AI_PROVIDER_HANDOFF.md) and [AUTO_DETECTION.md](AUTO_DETECTION.md) for exact interfaces and limitations.

Music search uses anonymous Openverse results filtered to CC0, Public Domain Mark, and CC BY; a user may also import authorized local audio. Fit places audio on a dedicated Music track with offset/trim or looping, gain, fades, and optional estimated beat markers while preserving picture and dialogue. Credits are revision-scoped in exports. Synthetic mix/decode, browser local-file import/Fit/export/credits, one live catalog import/decode, and native local-song Fit/reopen were checked. Catalog metadata is not rights clearance, beat estimates do not cut picture, and exact commercial songs may need to be supplied by the user with authorization.

## Build and validation commands

On a prepared Mac, source `.local/mac-env.sh` and use its Python 3.10+ runtime (`FILM_PYTHON`); the system Command Line Tools Python 3.9 is too old. The frozen source suite and corrected native AI-tool acceptance passed, as did final general launch/reopen and source-to-bundle equality checks. Rebuild the app to reproduce the bundle locally; the recorded binary hash identifies this installed build.

```bash
source .local/mac-env.sh
"$FILM_PYTHON" -m unittest discover -s tests -v
"$FILM_PYTHON" tests/real_editor_acceptance.py
"$FILM_PYTHON" tests/real_advanced_acceptance.py
"$FILM_PYTHON" tests/real_music_ui_acceptance.py
"$FILM_PYTHON" tests/real_detection_ui_acceptance.py

```
